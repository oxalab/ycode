# Future Release [v1.0.0]

# v1.0.0 — Dynamic Extension Runtime

The current extension loader (loader.go) uses JSON config files to register declarative extension metadata (tool definitions, flags, provider configs). This is a deliberate limitation — Go cannot dynamically load .ts/. js source files the way the original TS jiti loader does.

Problem: Only LoadExtensionFromFactory supports executable behavior (tool handlers, event callbacks, commands). The loadExtensionFromConfig JSON path cannot carry func fields — Execute, RenderCall, Handler, On callbacks are always nil. Existing TS/JS extensions are incompatible.

### Planned approach:
Embed a JavaScript runtime (goja) inside the Go binary. Extension authors continue writing JS factory functions. The loader discovers .js files, Goja interprets them, and Go-backed API functions are injected into the VM via vm.Set(). JS callbacks are stored as goja.Callable and invoked from Go at runtime. This preserves the original extension authoring UX while keeping everything pure-Go and cross-platform.

## Scope of changes:

 - Add goja dependency
 - New `loadExtensionFromScript(path, api)` function alongside the existing JSON path
 - Bridge every `ExtensionAPI` method into the JS VM (`RegisterTool`, `On`, `RegisterCommand`, `RegisterShortcut`,`RegisterFlag`, `SendMessage`, `SendUserMessage`, `RegisterProvider`, `UnregisterProvider`, `exec`, flag access, session/model/thinking-level getters/setters)
 - Handle Go↔JS type marshaling for callbacks (tool execute receives json.RawMessage args, returns structured results; event handlers receive typed event structs)
 - Add `.js` to `isExtensionFile` and wire script loading into the discovery pipeline
 - Inject Go-backed equivalents for commonly used APIs (`fs`, `path`, `exec`) since Goja has no Node.js stdlib
 - Decide on TypeScript support (add esbuild/swc transpile step, or require plain JS)


### Open questions:

- Async support: Goja lacks native async/await. Tool execute functions may need Promise-based interop or synchronous-only contracts.
- Sandboxing: Define what host APIs extensions can access and enforce boundaries.
- Whether to support WASM or Lua as alternative extension runtimes for performance-sensitive or non-JS use cases.
- Dependencies: github.com/nicholasgasior/goja (pure Go, no CGo, cross-platform)
