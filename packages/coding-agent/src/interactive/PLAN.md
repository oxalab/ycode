# Re-base the ycode interactive TUI on the pi-tui port

> Canonical plan for the `interactive` package (this directory). Co-located with
> the code so the plan and the implementation stay in sync. Phases ship one at a
> time behind `YCODE_TUI=pi`; the existing Bubble-Tea TUI stays default until
> parity, then is deleted.

## Context

The Go coding-agent's interactive TUI (`packages/coding-agent/src/core/tui/`, Bubble Tea) was migrated from a TypeScript app that was **built on** the `@earendil-works/pi-tui` framework. The migration **skipped the framework layer** and re-implemented the app directly on Bubble Tea's Elm/MVU model. That caused concrete problems:

- **Lost input/editor fidelity** (the primary driver): the editor (`packages/coding-agent/src/core/tui/components/editor.go`, 537 lines) has no undo / kill-ring / history / word-nav / bracketed-paste, and is hobbled by `bubbles` ("v1 exposes no cursor column"). Keys arrive only as `tea.KeyMsg.String()` — no Kitty protocol, no bracketed paste. Autocomplete is simplified; `@file`/path completion is deferred.
- **Duplicated primitives**: a hand-rolled width/grapheme/wrap lib (`packages/coding-agent/src/core/tui/components/visual_truncate.go`, 228 lines) reinvents what `packages/tui` already provides and tests; glamour-based markdown; a second key-matching path.
- **MVU friction**: a package-level `globalProgram` hack, `program.Send` event bridges, and fire-and-forget goroutines to force an imperative event flow into pure `Update()`.

We have since completed a **faithful Go port of pi-tui** (`packages/tui/` core + `packages/tui/components`, 197 tests green) and a **framework-agnostic semantic theme system already exists** (`packages/coding-agent/src/core/tui/theme/`, ~50 colors, the port of reference `theme/theme.ts`). The reference production consumer is at `reference/coding-agent/src/modes/interactive/`.

**Outcome:** rebuild the interactive TUI on the pi-tui port — reusing the theme system and the stable core contract — so the agent's `Subscribe` callbacks mutate the component tree and `RequestRender()` **directly** (no `tea.Msg`, no bridges). Deliver full feature parity with the current Bubble-Tea TUI **plus** the missing editor/input/autocomplete fidelity. Coexist behind a flag until parity, then delete the old TUI.

User decisions: **driver = missing input/editor features**; **strategy = full-parity rebuild**; **coexist until parity, then remove**.

## Approach

A new package `ycode/packages/coding-agent/src/interactive/` consumes the pi-tui framework + the existing semantic theme + the `*core.AgentSession` core contract, mirroring the reference `modes/interactive/` architecture (static container tree, event→component bridge, editor-swap selectors). A single env gate `YCODE_TUI=pi` in `launchInteractive` selects it; the Bubble-Tea TUI stays default. Phases are ordered so the editor/keys/autocomplete (the driver) lands first (P1), each phase independently runnable behind the flag.

## Architecture

**Package layout** (`packages/coding-agent/src/interactive/`, package `interactive`):
- `orchestrator.go` — `Orchestrator`: `NewOrchestrator`, `Run`, `Stop`, lifecycle; owns the `*tui.TUI`, the container tree, and the subscribe-cancel.
- `tree.go` — `buildStaticTree()`: `header → chat → pendingMessages → status → widgetAbove → editorContainer → widgetBelow → footer` (matches reference).
- `events.go` / `agent_events.go` — `AgentSessionEvent` + SDK `AgentEvent` switches → mutate tree → `RequestRender`.
- `theme_adapter.go` — build `components.MarkdownTheme` / `EditorTheme` / `SelectListTheme` from `theme.Theme`.
- `slash.go`, `session.go`, `keybindings.go` — salvaged command/session/keybinding glue.
- `components/` — ported reference components (editor, header, footer, messages, selectors, …).

Imports: `ycode/packages/tui`, `ycode/packages/tui/components`, `ycode/packages/coding-agent/src/core/tui/theme`, `ycode/packages/coding-agent/src/core`. **Never** `charmbracelet/*` — this keeps a clean deletion boundary for the old `core/tui`.

**Launch seam** (minimal, `cmd/ycode/runtime.go` `launchInteractive`, lines 326-359): after the scoped-models banner, branch on `os.Getenv("YCODE_TUI") == "pi"` → call a new `launchInteractivePi(...)` (in a sibling `cmd/ycode/runtime_pi.go`) that builds `interactive.NewOrchestrator(opts)` and `Run()`s it. The existing Bubble-Tea path is untouched. Env-var (not a CLI flag) so `cli.Args` parsing is untouched during the rebuild; flipping the default to `pi` at parity is one line. Print/RPC modes are untouched (they call `AgentSession` directly).

**Integration**:
- Lifecycle: `NewProcessTerminal()` → `NewTUI(term, WithHardwareCursor(...))` → `buildStaticTree()` → `SetFocus(editor)` → install keybindings → `session.Subscribe(listener)` (store cancel) → `eng.Start()`.
- **Event bridge**: `session.Subscribe` runs on the session's emitter goroutine. Each event creates/updates a component in the right container and calls `eng.RequestRender()` (thread-safe). SDK streaming/tool deltas (`session.Agent.Subscribe`) update the in-progress assistant/tool component in place. **No `program.Send`, no global program.**
- **Theme adapter**: `theme.Theme.Fg(ThemeColor, text)` already returns ANSI; wrap as `tui.StyleFunc`: `sf := func(s string) string { return t.Fg("mdHeading", s) }`. Map md*/border/selectList color slots to the pi-tui component-theme structs. On `theme.OnThemeChange`, rebuild the component themes + `RequestRender`. `HighlightCode` wires chroma (already a dep) into the `syntax*` slots.
- **Focus + selectors**: focus = `CustomEditor` by default. Selectors (`/model`, `/theme`, …) build a `components.SelectList`, **swap it into `editorContainer`** (`editorContainer.Clear(); AddChild(selector); SetFocus(selector)`), perform the action on a goroutine, then swap the editor back. Modal dialogs (login/oauth) use `eng.ShowOverlay(...)`. Key chords via `tui.KeybindingsManager` built from `core.AppKeybindings`.
- **Concurrency constraint (critical)**: `Editor.OnSubmit` and `SelectList` selection callbacks run **under the engine render lock** (synchronous input dispatch). They **must not** call `RequestRender()` synchronously (self-deadlock) — schedule session calls via `go func(){ session.Prompt(...) }()`. The subscribe goroutine mutates the tree only via the goroutine-safe helpers `TUI.InsertChildBeforeLast` / `RemoveChildSafe` (already added) or a dedicated `orch.mu`.

## Reuse vs port-fresh

- **Reuse as-is**: `core/tui/theme` (framework-agnostic ANSI; lipgloss import is only `ToLipgloss*`, harmless during coexistence, dropped at BT deletion), `core.AppKeybindings`, `SettingsManager`, model registry.
- **Salvage logic, re-skin**: slash-command routing (`app_commands.go`), event→component mapping (`app_events.go`), session calls (`cmdModel/cmdCompact/cmdFork/...`). The EventType switches and session-call logic are correct — replace `tea.*` returns with direct calls + editor-swap.
- **Port fresh from reference**: all `modes/interactive/components/*.ts` (they target the TS pi-tui API).
- **Do not port**: `visual_truncate.go`, BT `components/editor`, glamour rendering — superseded by `packages/tui`.

Rule of thumb: *logic touching only `core`/`session`/`settings` = salvage; anything returning `tea.*` or rendering via lipgloss/glamour = port fresh.*
